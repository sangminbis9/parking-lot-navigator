## 제출 전에 반드시 확인할 것

**해상도가 App Store Connect 규격에 맞지 않는다.** 7장 모두 **941×1672**인데,
6.9" 디스플레이 슬롯이 받는 세로 해상도는 **1290×2796 또는 1320×2868**뿐이다.
지금 파일을 그대로 올리면 업로드 단계에서 거부된다. 편집 원본이 남아 있다면
그 규격으로 다시 내보내야 하고, 원본이 없으면 앱 화면을 다시 캡처해 합성해야 한다.
가로세로 비도 다르므로(941×1672 = 9:16, 1320×2868 ≈ 0.46) 단순 확대로는 맞지 않는다.

파일명에 `5.`가 두 개(`5. 주차장 추천.png`, `5. 캘린더탭.png`)라 정렬 순서가 모호하다.
제출 순서를 정할 때 번호를 다시 매기는 편이 낫다.

## 앱 화면을 다시 뽑는 법

합성 전 원본 앱 화면이 필요하면 GitHub Actions → **App Store Screenshots** →
**Run workflow**로 macOS 러너 시뮬레이터 캡처를 받는다. `AppStoreScreenshotTests`가
지도·행사 목록·상세·상세 하단·캘린더·즐겨찾기·설정 순으로 8장을 찍고,
상태바는 `simctl status_bar override`로 9:41 / 100% / 신호 최대로 고정된다.
결과물은 1320×2868이라 그대로 6.9" 규격을 만족한다.
"Re-run jobs"는 원래 커밋을 다시 돌리므로 새 코드가 반영되지 않는다 — 반드시 Run workflow를 쓴다.
