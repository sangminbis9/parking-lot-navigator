# App Store 스크린샷

사용자가 직접 찍고 편집한 마케팅용 캡처다. 앱 화면 위에 마스코트와 카피 문구를 얹은 형태로,
이전에 여기 있던 CI 캡처 5장(`01-map.png` ~ `05-calendar.png`, run `34614345570`)은 이미 지웠다.

폴더 구성은 세 갈래다. **제출에 올리는 것은 리사이즈된 두 폴더이고, 최상위 7장은 편집 원본이다.**

| --- | --- | --- |
| (최상위) | 941×1672 | 편집 원본. App Store 규격이 아니라 **제출용이 아니다.** 다시 내보낼 때 기준이 된다. |
| `iPhone-resized/` | 1242×2688 | **6.5" 디스플레이** 슬롯 제출본 |

## 규격 확인 (2026-09-12)

**두 폴더 모두 App Store Connect 규격을 만족한다.** 이전 판에 있던 "해상도 미달" 경고는 해소됐다.

- `iPhone-resized/` 1242×2688 = **6.5" 디스플레이** 세로 규격. 아이폰 스크린샷은 6.9"를 올리지
  않는 경우 6.5"가 필수인데, 이걸로 그 요건이 채워진다. 나머지 아이폰 크기는 애플이 이걸 줄여서 쓴다.
- `iPad-resized/` 2064×2752 = **13" 디스플레이** 세로 규격. 이 앱은 `TARGETED_DEVICE_FAMILY`를
  따로 지정하지 않아 XcodeGen 기본값(아이폰+아이패드)으로 빌드되므로 **아이패드 스크린샷은 필수**다.
  13"는 아이패드 앱에 항상 요구되는 유일한 슬롯이고, 나머지 아이패드 크기는 여기서 파생된다.
- 알파 채널이 있는 PNG는 거부되는데 14장 모두 알파가 없다.

업로드에서 한 가지만 확인할 것: `iPhone-resized/` 7장과 `iPad-resized/`의 1~3번은 8-bit
**colormap**(인덱스 256색)으로 저장돼 있다. 애플 규격은 RGB 색공간을 요구하고 인덱스 PNG가
업로드 단계에서 걸렸다는 보고가 있다. 실제로 거부되면 truecolor로 다시 저장하면 된다:

```bash
mogrify -define png:color-type=2 "iPhone-resized/"*.png
```

## 앱 화면을 다시 뽑는 법

합성 전 원본 앱 화면이 필요하면 GitHub Actions → **App Store Screenshots** →
**Run workflow**로 macOS 러너 시뮬레이터 캡처를 받는다. `AppStoreScreenshotTests`가
지도·행사 목록·상세·상세 하단·캘린더·즐겨찾기·설정 순으로 8장을 찍고,
상태바는 `simctl status_bar override`로 9:41 / 100% / 신호 최대로 고정된다.
결과물은 1320×2868이라 6.9" 규격에 바로 맞는다.
"Re-run jobs"는 원래 커밋을 다시 돌리므로 새 코드가 반영되지 않는다 — 반드시 Run workflow를 쓴다.
